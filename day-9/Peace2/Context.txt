// REPRO - two sessions lock OrderId 100 and 200 in opposite order

Session A:
BEGIN TRAN;
UPDATE dbo.Orders SET Amount = Amount + 1 WHERE OrderId = 100;
WAITFOR DELAY '00:00:03';
UPDATE dbo.Orders SET Amount = Amount + 1 WHERE OrderId = 200;
COMMIT;

Session B:
BEGIN TRAN;
UPDATE dbo.Orders SET Amount = Amount + 1 WHERE OrderId = 200;
WAITFOR DELAY '00:00:03';
UPDATE dbo.Orders SET Amount = Amount + 1 WHERE OrderId = 100;
COMMIT;

// why it works, one line

A deadlock needs a cycle of waits - if every transaction locks rows in the same order, whoever gets there first just makes the other one wait normally instead of the two waiting on each other, so a cycle can never form
